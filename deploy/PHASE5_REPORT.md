## C. Visual system

Dark editorial surfaces, controlled lime/periwinkle accents, consistent typography, visible focus, touch-sized controls and native vertical media replace the earlier generic presentation. The three hero panels use original synthetic motion studies generated by `scripts/generate-samples.mjs`. Seven preset thumbnails and playable examples are actual FFmpeg outputs, not placeholder artwork.

`src/hooks/use-studio-motion.ts` scopes finite GSAP animations with `useGSAP`, media-query handling and cleanup. `src/app/creative.css` and `labs.css` provide responsive layouts. Heavy creative panels are dynamically imported. There is no continuously rendering canvas, video texture cache or WebGL requirement. Reduced motion removes nonessential spatial movement without removing actions; animations never gate generation or navigation.

Screenshots were inspected at 360, 390, 768 and 1440 pixels. Review led to a reliably reachable mobile Generate button, contextual sticky tabs, 16px mobile form text and real preset covers. Normal-motion desktop and reduced-motion mobile storyboard navigation were exercised. This is visual/functional QA, not a formal accessibility certification or a heap-leak benchmark.

## D. Rendering engine

The original seven presets still drive one FFmpeg implementation. Validated creative options feed shared timeline durations, source ordering, source-relative start offsets, safe text files, typography, opening/closing visibility, captions, audio and extracted covers. Text is passed literally, not interpolated as executable filter expressions. Invalid timing, indices and source references are rejected server-side.

Normalization preserves aspect ratio and handles rotation/resolution/frame-rate differences. Original audio crossfades now match video overlap; original synthesized soundtrack selection produces real AAC. Outputs remain 720 × 1280 H.264/AAC MP4 at 30fps. Silent mode is intentional. Cover changes do not intentionally alter the video filter graph.

Immutable private source snapshots are reused across exports of unchanged footage, expire with the session and are not publicly served. Jobs preserve queue limits, ownership, duplicate prevention, independent output paths, timeouts, recovery and cleanup. Stage reporting now follows actual normalization, composition and cover extraction. The five visible crew roles describe deterministic work; no LLM, invented thinking interval or fabricated progress percentage is involved.

## F. Performance

Production build reports 166 kB first-load JavaScript for `/` and `/festival`, versus the recorded Phase 5 baseline of 128 kB: an increase of 38 kB. Shared first-load JS is 103 kB; middleware is 34.5 kB. These are build estimates, not measured mobile network or interaction latency.

The new synthetic samples are approximately 53–60 kB each. Preset video previews load only when opened. The grain-heavy Retro Cam preview is approximately 4.33 MB; its effect has a real size cost. Creative panels are split out, motion is finite, and no idle WebGL render loop runs beside camera capture. No FPS, battery or physical-device memory numbers are claimed.

The API admission test exercised three sessions with one active and one pending slot, admitting two and rejecting the third safely. Peak observed video subprocess count was two. This establishes bounded behavior in this fixture, not festival throughput or thousands-of-users capacity. Keep one Node process and conservative queue settings.
